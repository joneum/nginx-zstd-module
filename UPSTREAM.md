Upstream reports
================

Everything that is open at
[tokers/zstd-nginx-module](https://github.com/tokers/zstd-nginx-module),
and where this fork stands on it.  Upstream has taken no change to its
code since April 2024.

Issues, fixed here
------------------

| | | |
|---|---|---|
| [#42](https://github.com/tokers/zstd-nginx-module/issues/42) | `t/suite/test` is not redistributable | The file was an article with a copyright and no licence grant. The corpus is generated by `t/suite/make-corpus.sh` now, so the repository carries nothing it was not given the right to pass on. |

Issues, left as they are
------------------------

| | | |
|---|---|---|
| [#3](https://github.com/tokers/zstd-nginx-module/issues/3), [#5](https://github.com/tokers/zstd-nginx-module/issues/5) | `text/html` is always compressed | nginx's own `gzip` works that way: `gzip_types` lists what comes in addition to `text/html`. Changing it here would make one compression module behave unlike the rest. The BREACH consideration of #5 applies to every content coding and belongs in the deployment, not in the module. |
| [#40](https://github.com/tokers/zstd-nginx-module/issues/40), [#36](https://github.com/tokers/zstd-nginx-module/issues/36), [#46](https://github.com/tokers/zstd-nginx-module/issues/46) | order against brotli, `q=` weights | The filter here is put next to gzip, for a dynamic build through `ngx_module_order` and for a static one through the re-ordering at the end of `filter/config`, because `auto/module` only evaluates `ngx_module_order` for dynamic modules. When a second third-party filter does the same thing, which of the two wins cannot be settled by either of them. For the two static modules there is no mechanism at all: the order follows `--add-module`. Honouring `q=` would mean one module arbitrating over another module's content coding, which nginx has no mechanism for either. |
| [#38](https://github.com/tokers/zstd-nginx-module/issues/38) | `ZSTD_c_targetCBlockSize` | Not implemented. |
| [#2](https://github.com/tokers/zstd-nginx-module/issues/2) | a dictionary is not standard compliant | True, and said so under `zstd_dict_file` in the README. |
| [#39](https://github.com/tokers/zstd-nginx-module/issues/39) | new release | This fork is released from its own tags. |
| [#18](https://github.com/tokers/zstd-nginx-module/issues/18), [#8](https://github.com/tokers/zstd-nginx-module/issues/8) | a load test resets the connection, compressed JavaScript is garbled | Old reports without a case that can be re-run. `ci/roundtrip.sh` compares what comes back with the original over 297 sizes and finds no difference. |
| [#13](https://github.com/tokers/zstd-nginx-module/issues/13), [#11](https://github.com/tokers/zstd-nginx-module/issues/11), [#4](https://github.com/tokers/zstd-nginx-module/issues/4) | a question about an ingress controller, a notice about Debian packages, a suggestion to register with two scanners | Nothing to do here. |
